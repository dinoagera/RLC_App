# Исправление запуска Unity на этом Linux-компьютере

## Результат

Исправлено 23 ноября 2026. Unity **6000.0.62f1** запускается; Windows Build Support (Mono) установлен. Unity импортировал и скомпилировал проект, выполнил тесты и собрал Windows Player.

Путь Editor:

```text
/home/dinoagera/Unity/Hub/Editor/6000.0.62f1/Editor/Unity
```

## В чём была проблема

Unity требовал `libxml2.so.2`, тогда как Ubuntu 26.04 содержит другую ABI-версию — `libxml2.so.16`. Создавать ссылку с одного имени на другое нельзя: это несовместимые ABI.

Совместимые библиотеки уже присутствовали в установленном GNOME Snap:

```text
/snap/gnome-42-2204/current/usr/lib/x86_64-linux-gnu/
```

## Что изменено

Только в пользовательскую папку Unity `Editor/Data/Tools/` добавлены:

```text
libxml2.so.2
libicuuc.so.70
libicudata.so.70
```

Это отдельные копии из GNOME Snap. Для них настроен локальный RUNPATH `$ORIGIN`, чтобы libxml2 находила свою совместимую ICU рядом с собой. Сам исполняемый файл Unity не изменялся.

`patchelf` получен из официального Ubuntu APT-репозитория и распакован в `/tmp/opencode/rlc-unity-compat`; системная установка пакетов не выполнялась.

**Не заменялись** `/usr/lib`, системная `libxml2.so.16`, глобальные пути загрузчика, настройки оболочки или исполняемый файл Unity. Поскольку Editor уже использует `Data/Tools` в собственном RUNPATH, запуск работает напрямую, включая запуск через Hub, без специальной оболочки с `LD_LIBRARY_PATH`.

Эти совместимые библиотеки нужны только Linux Editor. Они **не включаются** в Windows-сборку и не нужны на Windows-компьютере.

## Windows Build Support

Модуль установлен официальным Unity CLI:

```bash
unity install-modules --editor-version 6000.0.62f1 \
  --module windows-mono --yes --non-interactive
```

Успешность структуры Editor и Windows-модуля подтверждена:

```bash
unity editors verify 6000.0.62f1 --json
```

Проверка самого запуска:

```bash
/home/dinoagera/Unity/Hub/Editor/6000.0.62f1/Editor/Unity -version
```

Ожидаемый результат: `6000.0.62f1`.

## Обновление и обслуживание

Исправление относится к указанной папке Editor. При установке другой версии Unity проверяйте её отдельно: она может уже поддерживать системные библиотеки и не нуждаться в совместимых копиях. При обновлении GNOME Snap копии в Unity не обновляются автоматически; при необходимости их следует обновить из доверенного источника.

Для отмены локального исправления достаточно убрать **только три добавленные библиотеки**, перечисленные выше, из `Editor/Data/Tools/`. Это снова вернёт исходную ошибку запуска на нынешней Ubuntu. Никакие другие файлы Unity удалять не нужно.
